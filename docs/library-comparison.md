# 拍検出ライブラリ比較・採用記録

確認日：2026年10月29日。結論：今回のローカルプロトタイプには **aubio 0.4.9と拍追跡アダプター**を採用する。全曲で最良という結論ではなく、因果的処理、導入実績、今回の限定試験、条件を確認できるライセンスを合わせた判断。

## 候補の机上比較と利用条件

|候補|機能・条件|今回の判断|
|---|---|---|
|aubio 0.4.9|ライブ拍検出・BPM・信頼度。GPL-3.0-or-later。学習済みモデル不要|実際に導入・計測・採用。配布時はGPL対応が必要|
|BeatNet|CRNNと粒子フィルター、ストリーミング対応。本体CC-BY-4.0、依存にtorch/madmom/PyAudio等|今回の導入は保留。依存環境の構築負担が大きい。速度・精度は未計測で、aubioより劣るとは評価していない|
|madmom|コードBSD-2-Clause、付属モデルはCC-BY-NC-SA-4.0|将来の商用展開に対して付属モデルの条件確認が必要なため保留。未導入・未計測|

BeatNetがmadmomをimportすること自体は、madmomの非商用モデル使用と同義ではない。BeatNet自身のモデルと依存物の権利は別途評価すべきであり、本体ライセンスだけで商用利用可否を一括判断していない。

私的なローカル利用と、アプリを他人へ配布する場合の義務は区別した。GPLは商用利用を禁止しないが、カバーされる結合物を配布するときは対応ソースやライセンス条件への対応が必要。プロジェクト全体の公開・ライセンス設定は実施していない。今回のaubioは完全な改修済みソースとGPL本文を同梱する。詳細と他の実行依存物については `../THIRD_PARTY_NOTICES.md` を参照。

## 実測条件

Python 3.12 / NumPy 1.26.4 / aubio 0.4.9、開発用Mac上で実行。90/120/150 BPM × clean/room/quiet_roomの9条件、各30秒。元音源は本アプリのオリジナル合成打楽器。roomは持続和音・裏拍の高音・低域抑制・人工反射・白色雑音を加え、quiet_roomはさらに音量を下げた。これらはスマホの実録音ではなく、特定機種の音響モデルでもない。

各方式に同じ512サンプルのブロックを順番に与え、未来のブロックを参照しない。開始8秒から30秒までの予測拍と既知の拍を、許容±70 ms・一対一対応で評価。F1は過剰打撃と打撃不足の両方を数え、9条件を単純平均した値。BPM誤差は有効な推定区間のみの平均で、ロックできない時間はF1側で不足として評価する。処理時間は30秒音声を解析する計算時間の平均で、実時間の起動待ちや音声機器の遅延を含めない。

raw aubioは返されたBPMと最新拍を直接使用。aubio_adapterは採用する前処理・位相安定化・拍間隔補正を含む。計測値はこのマシンの1回の実行であり、一般的な性能ランキングではない。

## 読み取りと限界

従来方式より9条件平均の拍F1が改善し、解析の計算時間も短くなった。120 BPMのroom条件では従来方式が別の周期を選ぶ一方、採用方式は拍を追いやすかった。

ただし150 BPMのclean条件では従来方式が良く、150 BPMのroom/quiet_roomではaubioも半分のテンポを選ぶことがある。ロック開始が従来方式より遅くなる場合もある。これを隠さず、画面に倍・半分の補正操作を用意した。より広い曲種、反響、歌声混在、スマホの音響特性、実際のスピーカー出力を含めた精度は未検証。

計測後、固定seedの白色雑音と持続単音で誤ロックしない回帰試験を追加し、信頼度の下限を設定した。雑音の全種類への保証ではない。

## 実装した改善

- aubioのストリーミングテンポ推定を解析ワーカー内で使用。
- 弱い入力を過剰に増幅しない上限付きレベル調整。
- 複数の拍間隔を確認してから演奏を開始。
- 検出を一部取りこぼしても、拍数の整数倍を考慮して周期を補正。
- BPM・位相の小さな変動は徐々に追い、急なグリッド交換を抑制。
- 無音、古い解析結果、不確かな入力では打撃を抑制。
- 位相の変更による近接した二重打撃を抑制。
- ライブテンポの半分／倍補正操作を追加。
- Hitイベントと出力の境界を維持し、Arduinoへの差し替え設計を保持。

## 環境互換性

旧環境はPython 3.15。aubioとの互換性を重視し別の `.venv-audio` をPython 3.12で作成した。aubio 0.4.9のNumPy ufuncコールバック2箇所のconst修飾のみ修正し、現行clangの型不一致を解消。アルゴリズム本体は変更していない。変更表示と完全なソースは `third_party/aubio/` に保持。

## 確認中から進まない問題の修正

利用者から130 BPM・追従目安11%の報告があった。旧条件はaubioの生信頼度が0.5を超えることを必須とし、画面表示は raw/(1+raw) だったため、表示約33%以下では拍が検出されても開始できなかった。

修正後は従来の高信頼度条件に加え、生信頼度0.08超かつ直近2秒の入力RMS強弱比（90/10パーセンタイル）が1.35超なら、拍間隔が安定している場合に演奏を許可する。画面には無音・拍不足・拍間隔不安定・根拠不足・解析遅延を分けて表示する。表示11%でリズムの証拠がある入力を受け入れる回帰試験、無音理由表示、ノイズと持続単音の抑制を含め10件のテストを実施。上の計測表とJSONは修正後に再計測した値。

実際に利用者が流した音楽を録音・解析したわけではないため、報告環境での改善は再試用が必要。信頼度11%だけで演奏を無条件に開始する変更ではない。
