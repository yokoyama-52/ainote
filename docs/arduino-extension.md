# Arduino連携に向けた設計

今回の実装はPC出力のみで、未検証のモーター駆動やシリアル通信は含めない。

## 既存の境界

`music.Hit(time, velocity)` は曲先頭からの打撃時刻（秒）と0〜1の強さを表す。音楽の判断は `hits_between` にあり、画面やモーターに依存しない。

`output.PercussionOutput` は `schedule(hit)`、`render(start_frame, frames)`、`stop()` を定義する。現状は `PCOutput` が合成音を生成する。Engineは出力ファクトリを受け取れるので、実機用の出力実装へ差し替え可能。

## 実機時に追加すべき処理

PC音声コールバック内でシリアル送信やACK待機を行わない。独立したワーカーへ有限長キューで通知する。キュー満杯、切断、同期不良では新規打撃を停止する。

PC音声では現在のバッファに打撃を配置できるが、機構には先行予約が必要。実機用スケジューラーは現在時刻より先の100〜200 ms程度を予約し、変更・停止時には未実行の予約を取り消す。先読み時間は通信と機構の実測で決める。

曲時刻を音声ストリームのDAC再生時刻へ対応させ、さらにSYNC応答を使ってArduino時計へ換算する。機構の発音遅延を差し引いて動作開始を予約する。現在の画面用positionをそのまま実機時計として使用しない。

提案コマンドはHELLO / SYNC / SCHEDULE / CANCEL / STOP / HEARTBEAT。セッションID、連番、実行時刻、動作IDを含め、再送による二重実行を防止する。ACKは受理を意味し、実行完了とは分ける。

Arduino側で最小打撃間隔、可動範囲、予約上限、期限切れ、通信断停止を検証する。heartbeatと停止処理、物理停止スイッチはPCと独立に動かす。接続・再接続だけでモーターを動かさない。velocityは実測した動作IDへ変換し、自由な角度をそのまま送信しない。

## 追加する試験

偽の通信先を使った時刻同期・遅延・切断・重複・キュー上限試験を行い、その後にLED、最後に実際の打撃機構を接続する。音声の録音により命令時刻だけでなく実際の発音ずれを測定する。
