# 拍表示・開始時間の修正と、鼻歌対応の検討

2026年10月29日

## 1. 今回確認した不具合と修正

拍検出側は新しい拍に合わせて位相基準（phase）を更新するが、画面はその基準からの経過拍数だけで丸の位置を計算していた。新しい拍を検出するたびに経過拍数がゼロ近くへ戻り、最初の丸へ戻りやすかった。

修正後は基準時刻に対応する通算拍番号（beat_index）も保持し、基準更新後も1→2→3→4と進むようにした。表示は推定した拍のカウンターであり、曲の小節先頭の自動認識ではない。倍・半分補正と拍位置補正も表示へ反映する。

## 2. 開始時間の改善：実装済み

これまでの開始条件は、aubioのテンポ推定が成立し、複数の拍を観測し、信頼度と間隔の安定性を確認するというものだった。音源によって検出拍が疎になるため、20秒ほどかかる可能性がある。歌声の認識だけが原因と断定できず、今回の開始判定と推定器の立ち上がりも影響する。

追加した経路：

1. aubio.onsetのspecfluxで音の立ち上がりを検出する。
2. 直近4回の立ち上がりの間隔が規則的で、約55〜210 BPM相当、間隔の変動係数が8%未満、入力音に十分な強弱がある場合に仮追従を許可する。
3. 仮追従は音の立ち上がりを拍の候補とみなす暫定状態。盛り上げ度は控えめ相当（最大33）へ制限し、間奏による増打は行わない。
4. 通常のテンポ推定が成立したら通常追従へ切り替える。音の根拠がなくなれば待機へ戻す。単に待ち時間だけで演奏を始める変更ではない。

|合成音源|90 BPM|120 BPM|150 BPM|
|---|---:|---:|---:|
|元の練習用音源|2.02秒|1.53秒|1.23秒|
|人工反響・和音・裏拍等を加えた条件|8.18秒|3.53秒|2.83秒|
|同条件で小音量化|8.18秒|3.53秒|3.63秒|

これは各24秒の合成音源を順次入力した開発環境の結果であり、スマホ実録音・一般の実曲での保証ではない。通常推定への移行は約8〜14秒だった。4回の発音が必ず4拍とは限らず、裏拍や音符の長さ次第では倍・半分の誤認も残る。画面で補正できる。

## 3. 鼻歌への対応は別の認識経路が必要

現在の拍検出・仮追従だけで、ビートのない鼻歌へ十分対応したとはいえない。特に滑らかにつながる鼻歌は音の立ち上がりが少なく、長い同音からテンポを一意に決められない。音符1個＝1拍とする実装も、8分音符や長音で破綻する。

提案する構成：伴奏向けと鼻歌向けの入力モードを分け、共通の拍時計とHit出力へ接続する。

|段階|方法|狙い・制約|
|---|---|---|
|A：最初の実用案|ユーザーが4回タップして初期テンポと拍位置を与える。その後は声の発音と音高変化で少しずつ補正する|推定待ちを減らす。長音中も初期テンポで伴奏できる。完全自動ではない|
|B：鼻歌用の軽量解析|aubioのyin/yinfft等で音高と有声区間を推定。音高が一定以上変わった点、発声開始、長さをまとめて音符候補にし、半拍・1拍・2拍など複数仮説で拍時計を更新する|ビブラートを音符変更と誤認しない処理が必要。音符境界を直接打撃するのではなく、伴奏用の拍を推定する|
|C：全自動化の比較研究|歌声・非打楽器音向けのBeatNet+やSingNet系のモデルを評価する|歌声での研究実績はあるが、鼻歌・低遅延・手元のマイク環境での精度は別途検証。コード・モデルの利用条件と依存を改めて確認する|

A→Bの順を推奨する。保持したテンポを強く信じすぎず、短い息継ぎ・長音では継続し、長い無音では控える。曲を知らない状態で曖昧な音から拍を断定する代わりに、推定が不確かなときは疎な演奏へ戻す。

## 4. 鼻歌版を作る前に決める試験

- 同音の長音、音高が滑らかに動く鼻歌、音符間に切れ目のある鼻歌を分ける。
- 4拍のカウントイン後に、テンポ一定／徐々に変化／途中で休む条件を試す。
- 発音の検出精度だけでなく、伴奏の拍ずれ、開始までの時間、誤って打った回数を測る。
- まずタップ付きで成立することを確認し、その後にタップなしの自動推定と比較する。

## 5. 今回実装していないこと

タップを用いた鼻歌モード、音高解析、音符候補の統合、歌声専用ニューラルモデルの導入は未実装。今回追加したのは拍表示の修正と、規則的な発音に基づく仮追従である。
