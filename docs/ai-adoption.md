# AI拍検出モデルの比較・採用記録

2026年10月29日 / AINOTE PCプロトタイプ

## 採用した構成

Beat This! 1.1.0の軽量チェックポイントsmall0・small1を相互確認し、不一致ならaubioで補助する構成を採用した。2つは同じネットワーク構成の異なる学習seedによるモデルである。単一AIを常に使用する方式にはしない。

## 比較方法

90/120/150 BPM × 元の合成打楽器／人工反響・和音・裏拍・雑音を加えた条件の計6条件、各24秒、48 kHz。実曲やスマホの実録音ではない。

AIは先頭4秒から、以降1秒ごとに直近最大8秒の受信済み音声を解析する。窓の右端0.2秒は境界誤差対策として除外し、その過去の拍から次の拍を予測する。モデル内部は非因果的で、これは専用の因果ストリーミングモデルではないが、アプリでは未受信の未来音声は使わない。

計算時間も実測し、推論が終わった時刻以降にだけ新しい時計を使用する。新しい推論中も直前の有効な拍時計は継続する。開始8秒以降の予測出力拍を正解拍と±70 ms・一対一対応で評価し、過剰と不足を含むF1を6条件で平均した。

|構成|平均拍F1|最初の追従 秒|計算時間目安 ms|
|---|---:|---|---:|
|aubio|0.911|1.23〜8.18（不成立0条件）|0.1|
|small0|0.655|4.05〜8.13（不成立1条件）|123.3|
|small1|0.888|4.05〜5.10（不成立0条件）|128.9|
|ensemble|0.960|1.23〜4.11（不成立0条件）|345.9|

AI行の計算時間は窓推論1回の95パーセンタイルの条件間最大。aubio行は小さい入力ブロック単位なので単純な速度比較にはできない。初回のモデル読み込み、音声機器の入出力遅延は含まない。

AI単体は不検出・拍位置の違いによって従来方式より悪い条件もあった。採用構成は2モデルのBPM差が6%以内、拍位置差が35 ms以内の場合だけAIを使う。ほかはaubioを使い、画面で状態を示す。この構成で平均F1が改善した。ただし同じ6条件を設計・評価に使っており、未知曲への独立した評価ではない。実際の曲・スマホ・部屋での改善は再試用が必要。

## 実装と操作

run.command で起動 → リアルタイム入力 → 「AI 2モデル相互確認（推奨）」で開始。比較用にAI small0、AI small1、従来方式も選択できる。変更は停止中に行う。

- AIは別ワーカーで処理。最新優先キューは最大1つ、古い推論結果は採用しない。
- モデルのロードや推論を音声コールバック内で行わない。
- AIの準備中・不一致・エラー時は従来方式で補助し、無音時は打撃を控える。
- 起動直後のAIロード中もaubioの早期仮追従が可能。
- Hitイベントの境界を維持し、Arduino用出力への差し替え設計を残す。
- ファイル再生モードのBPM推定は今回は変更していない。
- 再取得：.venv-audio/bin/python scripts/fetch_models.py
- 比較再実行：.venv-audio/bin/python benchmarks/compare_ai.py
- 生の計測値：docs/ai-benchmark-results.json

## 検証

17件の自動テストと画面の認識方式切替を確認。実モデルによる合成音源推論、固定seedの白色雑音・持続単音・無音で相互確認が成立しないことを確認した。音声機器を使わず、実時間で入力を渡す別スレッド動作も確認し、AI相互確認への移行は約4.16秒、直近の推論は約247 msだった。実際のマイク・スピーカーでの試験はこの環境では実施できていない。
