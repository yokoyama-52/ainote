# AINOTE — カラオケ合いの手マシーン

Python製のPCプロトタイプです。既存の `仕様書.md` と `hello.py` は変更していません。

## 起動（Mac）

このフォルダの `run.command` をダブルクリックしてください。初回は練習用デモが入っているので、そのまま「演奏開始」で試せます。端末からは次の方法でも起動できます。

```sh
cd /Users/yuyuyu/workspace/ainote
.venv-audio/bin/python -m ainote
```

専用の `.venv-audio` に必要ライブラリをインストール済みです。再作成する場合：

```sh
python3.12 -m venv .venv-audio
.venv-audio/bin/python -m pip install numpy==1.26.4 setuptools==80.10.2 wheel
.venv-audio/bin/python -m pip install --no-build-isolation -r requirements.lock.txt
```

## 使い方

1. PCの出力音量を控えめにして「演奏開始」。合成されたタンバリン音とデモ伴奏が鳴ります。
2. 盛り上げ度を変更。0は休止、1〜33は2拍に1回、34〜66は毎拍、67〜100は半拍ごとです。
3. 間奏モードで演奏密度を一段階上げられます。盛り上げ度0が最優先です。
4. 自分の伴奏を試す場合「音源ファイルを開く」でWAV/FLAC/MP3などを選択します。M4AやDRM付きファイルには対応していません。形式の対応はlibsndfileの実装に依存します。
5. BPMを入力するか「BPM・拍位置を推定」を実行。推定は80〜160 BPMの一定テンポを仮定し、先頭90秒を解析します。周期性の値は精度保証ではありません。
6. 音が合わない場合はBPM・拍位置補正を調整。正の補正は打撃を遅らせ、負は早めます。タップは3回以上押すとテンポを更新します。タップは拍位置を合わせる機能ではありません。
7. 停止ボタンまたはSpaceで停止。開始は常に音源の先頭からです。

四つの丸は4拍の進行表示で、曲の小節先頭を自動検出しているわけではありません。音量を変えても伴奏の再生速度は変わりません。BPMを途中で変更すると現在の曲時刻から拍を再計算するため、位相が変わることがあります。テンポ変更は停止中の調整を推奨します。

音源はPC内で処理し、ネットワークに送信しません。通常動作では録音や元音源のコピー保存も行いません。

## リアルタイム入力モード（追加）

1. 起動後、モードを「リアルタイム入力」に切り替えます。
2. 入力機器と出力機器を選び「演奏開始」。macOSがマイクへのアクセスを求めた場合は許可してください。必要ならシステム設定のプライバシーとセキュリティで、起動元のターミナル等のマイク利用を許可します。
3. 別の機器で音楽を流してマイクで拾うか、オーディオ機器から伴奏を入力してください。PCの再生音を直接取り込むには、OS側のループバック／仮想音声機器が別途必要です。このアプリだけで他のアプリの音を自動取得する機能はありません。
4. aubioで拍とテンポを推定し、確かさが十分ならタンバリンを鳴らします。追従開始は曲によって数秒〜十数秒かかります。入力メーターが動かない場合はデバイス選択とマイク権限を確認します。
5. 盛り上げ度・間奏モード・拍位置補正・タンバリン音量はそのまま使えます。ライブ中のBPMは自動推定です。タップテンポはファイルモード用です。

入力音は再生しません。タンバリン音のマイクへの回り込みで自己追従する可能性があるため、タンバリン出力にはヘッドホンを推奨します。直接入力なら、伴奏だけを入力へ送ってください。出力音と入力音を同じ仮想デバイスへ混ぜないでください。

aubioの因果的な拍検出を使い、拍間隔と位相を滑らかに補正します。突然のテンポ変更、弱い拍、変拍子、倍・半分のテンポ誤認には限界があり、任意の音楽への正確な同期は保証しません。無音が約1.1秒続くか、分析更新が古くなると打撃を控えます。追従目安は推定の正解率ではありません。

`ainote/live.py` のTrackerが解析、LiveEngineが入出力を担当します。音声コールバックから有限長キューで別スレッドに解析を渡し、PC再生時刻へ拍を投影して既存のHitイベントを生成します。入力が欠落した場合は解析履歴をリセットします。生音声の保存・外部送信はありません。

検証：既存4件に加え、90/120/150 BPMのストリーミング合成音源、無音時のロック解除、未確定・古い推定での消音に加え、低音量入力・ノイズ・単音の試験も実施しました。実デバイスの入出力はこの実行環境にデバイスがないため未検証です。実際の曲・機器に応じて今後調整が必要です。

### 「確認中」のまま進まない場合の改善

表示11%などのテンポ候補を一律に除外していた開始条件を修正し、音の強弱と拍間隔の安定性も使うようにしました。旧画面の33%相当の基準を超えない限り永遠に待つ問題を解消しています。

アプリを閉じて `run.command` から起動し直してください。待機中は理由、検出拍数、入力レベル（dBFS）、入力欠落数が表示されます。無音なら機器とマイク権限、拍間隔不安定・根拠不足なら伴奏の明瞭さや周囲の雑音を確認してください。入力dBFSは0に近いほど大きい値で、以前の小数の入力表示とは単位が異なります。

### 拍表示と早期の仮追従

新しい拍を検出すると最初の丸へ戻りやすかった表示を修正しました。4つの丸は推定拍のカウンターで、曲の小節の先頭を認識する表示ではありません。

規則的な発音を4回捉えた場合は、通常推定より先に「仮追従」を開始します。仮追従中は控えめな演奏に制限し、推定が安定すると通常演奏へ移ります。開始時間は音源によって異なり、一定秒数での開始は保証しません。長音だけの鼻歌はまだ対応できません。今後の設計案は `docs/rhythm-following-next.md` にまとめています。

## AI拍認識（追加）

ライブモードの「拍の認識方式」は **AI 2モデル相互確認（推奨）** が標準です。Beat This!のsmall0とsmall1をPC内で動かし、2モデルの拍位置とテンポが合う場合にAIの拍時計を使います。不一致・準備中・解析失敗・結果の遅延時は従来のaubioで補助します。比較用に各AI単体と従来方式も選択できます。方式の変更は停止中に行ってください。

モデルは約8 MBずつで取得・検証済みです。`run.command` から起動し、ライブモードでお試しください。画面にはAI採用中か、AIの判断待ち／不一致で従来方式を使っているかを表示します。ファイルモードのBPM推定は従来の処理のままです。

AIは直近最大8秒の受信済み音声を1秒ごとに解析します。元のモデルは因果的なストリーミング専用ではなく、このアプリで過去の窓に適用し、そこから次の拍を予測しています。AI結果が出る前もaubioの早期仮追従を使えます。AI処理は別スレッド・最新優先のキューで行い、音声コールバックでモデルの読み込みや推論を行いません。

モデルがない／破損している場合は従来方式で動作し、理由を表示します。再取得は `.venv-audio/bin/python scripts/fetch_models.py`。通常の起動ではインターネットからモデルを取得しません。インストール時のみPyPI・公式モデル配布元へ接続します。音声は外部送信・録音保存しません。

比較は合成音源6条件で行い、実際のスマホ／部屋／楽曲での精度を保証するものではありません。AI単体は従来方式より悪い条件もあるため、2モデル相互確認＋従来方式の補助を採用しています。モデルや音源の権利を含む記録は `docs/ai-adoption.md` と `THIRD_PARTY_NOTICES.md` を参照してください。

## 一定BPMを優先する安定化（2026-10-29）

ライブ演奏に独立した拍時計を追加しました。AIと従来方式を切り替えるたびに時計を置き換えず、同じ時計を継続します。

- 初期BPMは最も近い整数へ丸めます（切り上げによる速い側への偏りを避けます）。
- 固定したBPMの±3以内の推定差ではBPMを変更しません。
- それより大きな変更は、近い候補が6秒以上・4回以上続いた場合のみ採用します。同じ検出結果の繰り返しは回数に数えません。
- 半分・倍など大きな変化は自動採用しません。手動の拍間隔補正か「テンポを取り直す」で対応します。
- 拍位置は一瞬で飛ばさず、最大0.04拍/秒の範囲で滑らかに補正します。ずれが大きい観測は補正に使いません。
- 音が続いている場合、認識不成立でも最後に有効だった推定から最大8秒は同じリズムを維持します。画面に継続中と残り時間を表示します。
- 無音が約2秒続いた場合、または長く認識できない場合は停止して再確認します。音声処理スレッドの停止・入力切断時の保護は別に維持します。

曲が変わった場合や、最初に間違ったテンポを固定してしまった場合は「テンポを取り直す」を押してください。音声入力・認識・拍時計を再起動します。一定BPMの曲を優先する設定なので、実際にテンポが変わる曲への追従は遅くなります。

検証では推定値を118〜122 BPMの間で変動させても60秒間120 BPMを維持し、予定打撃間隔は0.5秒でした。短い認識途切れ、無音、半分・倍の誤認、継続するテンポ変更、拍番号の継続も試験しました。これは実際のマイク・曲での性能保証ではありません。

## 低音抽出・移動窓の検証と改良

AIの元音声は全帯域のまま保持しています。低音だけをAIへ入力する変更はしていません。AIは従来どおり直近最大8秒を1秒ごとに解析します。5秒窓との比較では悪化する条件があり、標準の窓は短縮しませんでした。

今回採用した改善：
- AIが返す直近複数拍について、拍間隔の中央値だけでなく、拍列全体の傾きと位置を頑健に推定します。20 ms単位の拍位置丸めによるBPMの揺れを抑えます。
- 仮追従で半分のテンポをつかんだ場合に、その値が固定され続ける問題を修正しました。未確定の間だけ、確定した推定が2秒以上・3観測以上続けば初期テンポを訂正します。確定後の±3 BPM無視、保持・停止のルールは維持します。

任意の「低音域の補助解析（30–150 Hz・5秒窓）」も追加しました。30 Hz以下の振動を減らし、150 Hz以下の低音から周期を推定します。主判定とBPM・拍位置が合うときだけ軽く補正し、低音だけで演奏を開始したり、異なるテンポへ上書きしたりしません。今回の比較では全条件の改善を確認できなかったため、**標準はOFF**です。停止中にONへ切り替えて試せます。従来方式のみを選ぶ場合には適用しません。

Geminiの提案にある「低音を使えば劇的に精度が上がる」は曲や入力環境によります。低音の弱い曲やキックが2拍に1回の曲では、手掛かりが不足したり半分のテンポを選ぶことがあります。低音で支持されないときも、全帯域AIの判定を否定しない構成です。

詳細・比較値は `docs/bass-window-review.md`、再実行は `.venv-audio/bin/python benchmarks/compare_bass.py`。音声の外部送信や録音保存、新しいモデル・依存ライブラリの追加はありません。

## 毎回一定して後ろで鳴る場合

BPMが遅い場合（時間とともにずれが広がる）と、発音タイミングが一定して遅い場合は調整を分けます。固定した遅れでは、テンポを上げる代わりにライブの「10 ms早める」を使ってください。マイナス値で早く、プラス値で遅く鳴ります。まず3回（−30 ms）ほど早めて聴き比べ、10 ms単位で調整できます。「補正を0に戻す」で元に戻せます。

ライブ用の補正値は保存し、ファイルモードの推定拍位置とは分けました。音楽を変えても同じ機器構成なら補正を引き継ぎます。スピーカー・ヘッドホン・入力機器を変えた場合は再調整してください。実測した自動校正ではなく、耳で合わせる固定時間補正です。最適値をこちらから推定・設定はしていません。

30 msの前倒しで予定打撃時刻だけが30 ms早まり、拍間隔は変化しないことをテストしました。実際の出力音や機器固有の遅れは手元で確認が必要です。

## ヘッドホンが機器一覧に出ない場合

演奏を停止して「機器更新」を押すと、音声エンジンを再初期化して機器一覧を再取得します。起動後に接続した機器も再走査の対象です。モノラル出力のヘッドセットも一覧へ含め、モノラル出力へ対応しました。ファイルモードでも出力先を選べます。取得失敗時は理由を表示します。

ヘッドホンを接続 → OSのサウンド設定で接続・出力先を確認 → アプリで停止 → 機器更新 → 出力先を選択 → 開始、の順で試してください。機器名が出ない場合でも、OSでそのヘッドホンを出力先にして「標準の音声出力」を選ぶ方法を試せます。OS自体が認識していない機器をアプリだけで追加することはできません。有線のアナログ端子は独立した製品名でなく、内蔵出力などの名前で列挙される場合があります。

音声ライブラリに公開の再走査APIがないため、固定したsounddevice 0.5.6の初期化APIを `ainote/devices.py` に隔離して使用しています。再初期化はすべてのアプリ内ストリームを閉じた停止中だけ行います。実際のヘッドホンはこの実行環境では確認できていません。

### マイク入力の拍位置補正（2026-10-29）

内部BPMは小数のまま保持します。近いBPMの候補が狭い範囲で5回続いた場合だけ、小数BPMを緩やかに微調整します。小さな拍位置誤差は連続補正し、より大きな誤差は3つの異なる拍候補が同じ方向で一致した場合だけ補正します。半拍ずれや単発の候補では拍を飛ばしません。確定後の半分・倍の候補も、現在の拍間隔へ合わせて位相補正に利用します。

提供録音の10〜23秒を、各時点までの最大8秒窓で再解析しました。録音全体に対するsmall1モデルの推定拍を参考として比較すると、誤差中央値は4.31→6.89 ms、90パーセンタイルは20.72→20.00 msでした。参考拍は正解ラベルではなく、全指標での改善を確認したわけではありません。非同期計算・機器の入出力遅延は再現していません。一定の出力遅延が残る場合は「早める／遅らせる」を利用してください。
